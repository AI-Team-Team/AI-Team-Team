# 1. Foundation: An Agent Is One Continuing Person

[Back to blueprint index](README.md).

## Confirmed Direction

> An Agent is one continuing individual, not a disposable role, a team-local copy, or an execution slot that can be cloned when another activity needs attention.

The same Agent retains its identity, personal instructions, memory, model binding, personal inbox, Private DocLib, and personal activities across team memberships.

Joining or leaving an AgentTeam changes only the membership relationship rather than modifying any Agent-owned field.

Personal instructions, model binding, memory, inbox, private artifacts, and personal task ownership remain the individual's own state rather than fields reconfigured by membership changes.

A conversation, work item, background execution, or new team must not implicitly create another version of the same person.

Creating a genuinely different Agent is different from making concurrent copies of an existing individual.

One Agent may belong to several AgentTeams and maintain several conversations without becoming several independently executing people.

Different Agents may act concurrently, but one Agent's model activity must remain coordinated through its single continuing identity.

A background execution may continue while its owner handles another matter without becoming a second model-driven copy of that owner.

If a background execution later needs the owner's judgment, that requirement returns to the same person's activity mechanism.

Technical synchronization remains necessary to protect personal memory, invocation context, authorization checks, and state commits.

Removing discussion rounds does not mean removing all locks or allowing concurrent mutation of one person's Working Context.

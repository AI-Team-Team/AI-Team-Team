# Ownership and Retained Evidence

ATT separates the owner of personal state, the authority for a current operation, and the historical subject of a retained record.

## Ordinary Identities

One ordinary Agent UUID owns its instructions, saved model alias, personal window, inbox, Journal provenance, private library, and personal executions.

Current membership and historical membership intervals refer to that same person without copying or reconfiguring its owned state.

A team's creator is immutable provenance, while its optional organizational parent is current topology authority.

Retained and dead creators remain valid historical subjects without needing a live model binding.

The current Root remains active and protected, with its own Agent identity rather than a special substitute voter.

Runtime clients must have stable aliases, and all missing active bindings are reported explicitly before restore publication.

## Sources, Views, and Authority

Shared chat sources are separate from each recipient's live or frozen view, captured reminder preview, read watermark, and personal deletion.

Concrete membership intervals authorize team history before counts, pagination, searches, previews, and references are produced.

Direct contact controls neither grant DocLib access nor supply organizational consent.

An execution retains its original owner and captured scope even when that owner later changes memberships or invocation scope.

Lawfully accepted task results remain owner-readable after source revocation by default, with the strict Host-controlled restrictive mode described in [Background Tasks](../Background_Tasks.md).

Source authority is rechecked before accepting a new result, including exception-derived content, so a revoked source cannot create a newly retained disclosure.

## Temporary Supervisory Identities

Each assessment uses a genuine registered temporary AgentTeam and fresh restricted Agents on the common runtime.

Their live identities, libraries, and reusable personal windows are excluded from ordinary snapshots even when a full save happens during an audit.

Dedicated audit records retain the actual participants, permitted evidence, scoped model requests and tool outcomes, findings, and final assessment after teardown.

The common services select this trusted lifecycle profile; an Agent cannot request an audit persistence bypass through tool arguments.

Audit subjects may be an Agent, AgentTeam, or ATT, without representing ATT as a fabricated Root subject.

Restore validates these forensic references and interrupts unfinished assessments without reconstructing participants or replacing their identity with Root.

## Private and Transient Content

Private DocLib contents enter a model workflow only through deliberate authorized operations.

Generic event payloads, callbacks, operation receipts, task metadata, and directory counts contain their explicit metadata allowlists rather than private bodies or raw arguments.

Committed personal windows must be provider-valid and retain transient-content redaction.

An unfinished Native exchange is retained as factual invocation/execution evidence but excluded from the restored model window.

The optional memory catalogue stores deliberate sanitized invocation material and remains disabled by default.

Neither the Journal nor audit or execution records capture provider-hidden reasoning or infer an internal monologue.

## Runtime Bindings

Model clients, generator handlers, tools, resource resolvers, executor connections, auditors, callbacks, clocks, locks, Tasks, and coroutine stacks are Host-owned runtime bindings.

They are not serialized or reconstructed from historical tool names and external handles.

After successful restoration, the Host reacquires Agent and team objects from the published manager while their persistent identities and retained state remain the same.

# 9. AI-Authored Work in Existing DocLibs

[Back to blueprint index](README.md).

## Confirmed Direction

Work means what the AIs are doing, not exclusively a request with measurable acceptance conditions.

An AI may write a novel, investigate a possibility, develop software, or pursue an evolving idea without a universal framework-defined completion state.

ATT must not require every activity to have a requester, an external verifier, a testable result, or a deadline.

The participating AIs may deliberately establish such details when they are useful for their own work.

Existing personal and team DocLibs are the place for AIs to create plans, research notes, progress descriptions, evidence, and their own judgments when useful.

This update does not require a separate WorkItem table, dedicated work tools, compulsory progress fields, or a framework acceptance state machine.

The framework tracks execution and notification facts needed for reliability without interpreting the meaning of those AI-authored work documents.

A tool execution completing, a model response returning, or a health audit passing does not automatically complete the associated work.

A team migration or an interrupted conversation must not silently complete, delete, or replace the AIs' work artifacts.

The framework must not create a preset business-review Agent to determine whether the work is worthwhile, progressing, or finished.

If AIs choose to express a collective completion judgment, ATT must not infer that judgment from chat inactivity or personal-mail state.

This update does not introduce a mandatory completion-voting interface or select a voting threshold for ordinary work.
